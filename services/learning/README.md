# services/learning/ —— 持久学习闭环：摸底 → 计划 → 任务 → 完成 → 重排 → 面试训练怎么落到文件与表

这一层把能力 agent 拼成一条**可恢复**的学习流程：每个环节的产物都写成一份带作用域（user_id + exam + 学段 + 科目 + 档位）的文档存进 SQLite，页面刷新或进程重启后按同一作用域接回原状；题目本身始终来自 `services/knowledge/repository.py` 的真实索引，提交始终走 `Workbench.submit` 那一条判分/记账链路，本层不自己算对错。写它的是 `services/web/routes.py`（`include_router(learning_router(workbench))`）和 `services/web/service.py::Workbench.chat`（PLAN 意图时直接调 `learning.create_plan`），读它的是 `web/app.js` 与 `web/workflows.js`；状态文件是 `.local_state/learning.sqlite3`（与 `workbench.sqlite3` 同目录、另一个连接，不入库）。对外路径全部在 `/api/v1/web/learning/` 下：`POST /diagnostic/start`、`/diagnostic/result`、`/plan`、`/plan/current`、`/plan/replan`、`/task/start`、`/task/complete`、`/interview/session`、`/interview/session/current`、`/interview/session/answer`（`services/learning/router.py::build_router` 的 `prefix='/learning'` 再嵌在 web 的 `/api/v1/web` 下，因此共用那道运行时令牌校验）。

改动后跑（本轮实测：`tests/test_interview_session.py` 6 passed / 10.70s；`tests/test_exam_sessions.py + tests/test_learning_workflow.py` 合计 17 passed / 64.02s）：

```powershell
$env:KNOWLEDGE_MAP_STATE_DIR = "D:\tmp\kb_state_check"   # 学习文档与回执都跟着这个目录走
python -m pytest tests/test_learning_workflow.py -q
python -m pytest tests/test_interview_session.py -q
```

## 文件清单

- `models.py`（45 行）—— 全部继承 `services/web/models.py::WebContext` 且 `extra='forbid'`：**只有上下文与意图能进请求，进度一律从存储里读**。`DiagnosticStartRequest(request_id, item_count=8 ge=1 le=30)`、`DiagnosticResultRequest(diagnostic_id)`、`PlanCreateRequest(request_id, days_until_exam=30 ge=1 le=180, daily_available_minutes=60 ge=15 le=360)`、`PlanReplanRequest(request_id, plan_id)`、`TaskRequest(plan_id, task_id)`、`InterviewStartRequest(request_id)`、`InterviewAnswerRequest(request_id, session_id, task_id, answer_text 1–20000, duration_seconds? gt=0 le=7200)`。`request_id` 是幂等键，配套 `LearningStore.replay`。
- `store.py`（83 行）—— `LearningStore(workbench)`。库文件位置：先 `PRAGMA database_list` 取 Workbench 那份 SQLite 的路径、用它的父目录（默认即 `.local_state/`），`KNOWLEDGE_MAP_STATE_DIR` 存在时以它为准，然后打开同级的 `learning.sqlite3`（`check_same_thread=False, timeout=30`，`PRAGMA journal_mode=WAL`）——注释写明这是为了让"自带临时库的测试"把所有关联文件留在同一处。两张表：`learning_documents(id, kind, scope, data)` + `learning_documents_scope(scope, kind)` 索引、`learning_receipts(scope, action, request, fingerprint, resource)` 主键 `(scope, action, request)`。`scope_data(ctx)`/`scope_key(ctx)` 把 `user_id/exam_type/school_level/subject/trust_tier` 折成一个指纹（`services/memory/receipt.fingerprint`），这是"换范围就读不到别人的文档"的实现点。`transaction()` 是 `RLock + BEGIN IMMEDIATE` 的上下文管理器（共享这份库的两个 workflow 进程因此串行，异常回滚）。`get/latest/save`（`ON CONFLICT(id) DO UPDATE`）读写文档；`replay(req, action)` 命中同 `request_id` 时比对 `fingerprint(req.model_dump(mode='json'))`，参数改过抛 409"请为新操作使用新的 request_id"，没命中返回 None；`receipt(req, action, resource)` 落回执。本文件不碰知识库数据（模块 docstring：no mutable library data lives here）。
- `workflow.py`（353 行）—— `LearningWorkflow(workbench)`（`self.store = LearningStore(workbench)`、`self.interview = InterviewTrainer(workbench, self.store)`）。七个环节按调用顺序：
  1. 池子与口径：`_metas` 用 `repo.find_questions(exams, school_level, subject)`；`_pool(ctx, objective=False)` 依次要求 `meta.has_answerable_text`、`TrustGate(tier).classify_meta(meta).servable_in_paper`、非缺图（`repo.has_unavailable_figure`）、`classify_record(record).servable_in_paper`，`objective` 时再加"单选/多选 + 有 node_ids + `gate.reconcile_verdict(record, answer, None)[0] is not None`"，听力题没本地音频（`repo.audio_path`）直接剔除；`_scope_nodes` 把题面挂载的考点与图里 `knowledge_node`（NTCE 按 `ntce.<学段>.<科目>.` 前缀过滤，CET 不许被 NTCE 式过滤放宽成空域）并成"这一范围到底有多少考点"。
  2. 发卷：`_spread(pool, count)` 贪心选"覆盖最少见考点"的题；`_issue_selected` 经 `workbench.practice(WebPracticeRequest(practice_mode='error_elimination', wrong_question_ids=...))` 真实成卷（卷面归属、材料、答案下发口径全归 Workbench），随后只 `UPDATE papers SET data=?` 改显示标题；空池 409。
  3. 摸底：`start_diagnostic` 在 `store.transaction()` 里先 `replay` 再发卷，写 `diagnostic-<hex>` 文档 + 回执；`diagnostic_result`/`_diagnostic_view` 用 `workbench.diagnostic.evaluate(DiagnosticRequest(submissions=真实提交))` 出报告，`complete = len(submissions) == paper['total_items']`，并给 `_coverage` 的 scope/available/selected/covered/uncovered/unavailable 六组考点 id，notices 里钉死"不提供正式分数、能力估计或通过概率""未覆盖部分不作掌握度判断"。
  4. 计划：`create_plan` 调 `CurriculumPlannerAgent(repository=wb.repo, store=wb.memory.store).generate_plan(PlanRequest(..., current_mastery=self._mastery(req, nodes)))`，然后按 `by_node = Counter(考点→题数)` 把库里没有题的任务剔掉，给每个任务补 `task_id/status='pending'/paper_id=None/required_submission_count/submitted_count/completed_at/mastery_score`，重算 `day['total_minutes']`，写入 `plan-<hex>` 文档（含 `budget_minutes`、`scheduled_minutes`、`revision=1`）；任务全被剔光则 409。
  5. 任务开始：`start_task` 幂等——已有 `paper_id` 就直接回原卷；`mock_sprint` 走 `workbench.practice(practice_mode='mock_exam', item_count=100)` 并要求无 `input_blocked`，其它按考点过滤池子、`fsrs_review` 再与 `workbench.memory.due_question_ids(user_id, limit=100)` 求交，`_spread` 后 `_issue_selected`；`required_submission_count` = 实际可提交题数，少于 `target_question_count` 时写 `shortfall_notice`（完成条件按实际发卷数，不按原计划数）。
  6. 完成核对：`complete_task` 只认 `_evidence(paper)`（有 `submitted_at` 且有 `user_answer`、且题目未被 `input_blocked` 的提交行，读 `workbench.store.paper_submissions`），不足则 409"请完成实际答题后再结束任务"；首次完成才置 `completed` 并触发 `_rank_pending`、`revision += 1`。
  7. 重排：`_rank_pending` 只在 `status=='pending'` 的任务之间换位，优先级 `fsrs_review` 最前、其次 `is_weak(mastery_score)`（线在 `services/common/weakness.py`）、再次无记录、最后已掌握，且换位必须两天的 `total_minutes` 都不超 `daily_available_minutes` 上限；`completed_minutes`/`status` 随之重算，notice 明说"无记录考点不设默认掌握度，已完成与进行中任务保留"。`replan` 只做这件事 + 版本号；`current_plan` 在 `published` 档返回 `{'plan': None}`。
- `interview.py`（301 行）—— `InterviewTrainer(workbench, store)`，一场可恢复的 NTCE 面试训练（三阶段：结构化问答 → 试讲转写测算 → 20 分钟简案）。组场：`_stages` 从 `services/knowledge/learning_resources.py::LearningResources.list_scenarios(exam)` 取情境资源，`_qa_task` 要求该行绑定的 `exam_requirement_ids` 至少有一条能在库内核到（`repo.get_requirement`），题面用 `scenario_stem(summary)`（截 `「…」` 框架之前的情境原文，剥掉 `遵循/构建/按照/依据` 连接词）、框架用 `framework_of`（取长度 ≥12 的最长「」段）、采分点用 `framework_points`（含 `+` 按分层切、否则按顿号切，最多 6 点并记录切分口径）；`_design_topic` 用 `repo.find_questions(exams, question_types=('教学设计','活动设计'), require_nodes=True)` + `TrustGate.classify_meta(...).usable` 选一道真实题面。三阶段都空则 409"不虚构题面"。判分：`_grade_qa` 读 `repo.find_rubric(task_type='interview_qa', exam='NTCE')`（库里 20 分制、`review.status=needs_fix`），点级比对用 `services/grader/evidence.py::coverage`，维度反馈用 `dimension_feedback`，`total_score` 恒 `None`、`score_basis='none'`；试讲/简案走 `workbench.interview_agent.analyze_speech` 与 `review_lesson_plan`（即 `services/interview/`）。追问：`_follow_up` 只钉在本次没比对到的第一条框架步骤上，全命中则收拢到资源自带的 `exam_focus`。状态机：`pending → awaiting_follow_up → done`（每个任务只记一次作答，重答 409），`_view` 里 `_HIDDEN_WHILE_PENDING = ('reference_framework','points','points_from','missed_points')` 保证提交前不透题；`_guard` 拒绝 `published` 档与非 NTCE。文档 kind 为 `interview`，`current` 在 published 返回 `{'session': None}`。
- `router.py`（54 行）—— `build_router(workbench)`：`APIRouter(prefix='/learning', tags=['learning'])`，实例化一个 `LearningWorkflow` 并把上面十个路径接到对应方法（面试三路由 `flow.interview.start/current/answer`）。docstring 说明运行时鉴权由父路由提供。
- `__init__.py`（5 行）—— 转出 `LearningWorkflow` 与 `build_router`（`services/web/routes.py` 与测试都从这里取）。

## 改这里之前要知道的

- 状态文件是 `.local_state/learning.sqlite3`（含 `-wal`/`-shm`），不入库、按机器隔离：清库等于清空摸底记录、计划与面试会话；测试/验收一律先设 `KNOWLEDGE_MAP_STATE_DIR`（`tests/test_learning_workflow.py` 的 fixture 还会替换 `wb.memory` 的 store，见该文件第 23 行附近注释——它以前用 `Workbench.__new__` 手挑字段，漏赋 `exam_sessions` 让五条用例一起红过）。
- 与 `workbench.sqlite3` 是**两个连接、不是一个事务**：`start_task` 会同时写 papers（Workbench 的锁）与 learning_documents（本层的 `BEGIN IMMEDIATE`），中途崩溃会留下"有计划任务已 in_progress 但页面看不到卷"的窄窗口；默认只跑一个 worker，别在这里加跨库提交假设（`docs/web_agent_architecture.md` 记着这条口径）。
- 完成/进度只认真实提交：`_evidence` 过滤掉 `input_blocked` 题与空 `user_answer`，`required_submission_count` 由实际发卷数决定。想"点一下就算完成"必须改这里的数据来源，而不是加个布尔参数——那会让计划显示的 `completed_minutes` 变成编的。
- `_rank_pending` 的不变量：不新建任务、不改 `task_id`、不动 completed/in_progress 任务、换位后两天的分钟数都不越预算；`mastery_score` 缺失就当"无记录"排在已掌握之后，不给默认值。
- 面试训练的三个透题点：`_HIDDEN_WHILE_PENDING`、`scenario_stem` 只取框架前那段、`_guard` 的"非 NTCE/已发布档不开场"。`CET` 范围或 `published` 档请求这些端点应该拿到 409/`session: None`，`tests/test_interview_session.py::test_published_and_cet_scopes_never_fabricate_a_session` 就在钉这一条。
- 整层不出分：诊断报告、面试反馈、计划里都没有正式分数或通过概率；相关 notices 是给人看的口径文本，前端 `web/app.js::notices()`、`web/workflows.js` 会原样展开，改动会同时出现在"学习计划""知识点学习""面试练习"三个视图。
