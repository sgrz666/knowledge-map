# services/qa/ —— 答疑门面：讲解卡与苏格拉底引导怎么分发、每句引用从库内哪个字段取

这里是"题问 → 带出处的讲解"那一层：`TutorQAAgent` 自己不持有任何知识，把请求的 `question_id` 打到知识库记录上，由 `TrustGate` 决定当前档位能展示什么。调用入口：`services/app.py` 的 `POST /api/v1/qa/query` 与 `GET /api/v1/qa/stream`（SSE 推 qa_card，mode 参数缺省 `sparks_three_chain`）、`services/master/agent.py`（意图路由后转 `answer_query`）、`services/web/service.py::Workbench.submit`（客观题判分后附带讲解）、`web/app.js` 的提示按钮（传 `mode:'socratic_hint'`）。本目录只读库不写盘；引用取不到就声明取不到，不代拟结论。改动跑 `python -m pytest tests/test_services_all_agents.py -q`（`TestTutorQA` 类），"讲解卡正文不许断言答案"的数据侧断言在 `tests/test_services_data_source.py::test_qa_card_bodies_do_not_assert_an_answer`。

## 文件清单

- `agent.py`（75 行）—— `TutorQAAgent.answer_query(req: QARequest)` 分发：`req.mode` 在 `services/common/models.py:462` 定义为 `Literal["sparks_three_chain", "socratic_hint"]`（缺省 `sparks_three_chain`）——`socratic_hint` 走 `SocraticTutorEngine.hint(question_id, hint_turn, user_selected_option)`，其余（含缺省）走 `SparksChainEngine.explain(question_id, user_selected_option)`；苏格拉底链内部再按 `hint_turn` 1/2/≥3 分三段推进，所以学习者侧感知到的是"直接讲解 / 分步引导 / 末段揭晓"三种回答形态。`_gate_for`：注入的 gate 只在档位与请求一致时复用，否则按请求档位新建 `TrustGate`。`search_question_id(keyword, exam=None, limit=5)` 子串匹配 question_id 或题干前 80 字符，返回带 `review_status` 的命中列表——给调用方拿真实 id，而不是编一个。
- `socratic.py`（173 行）—— `SocraticTutorEngine.hint(question_id, hint_turn, user_selected_option) -> SocraticHintResponse`。逐轮内容全部引用库内字段：turn 1 引 `content.stem`（`_clip` 截 120 字）要求划主语/条件/设问词；turn 2 引 `content.options[].key` 列表要求找两个与限定条件冲突的干扰项，`user_selected_option` 非空时追加反向检验句；turn ≥3 才揭晓，且必须 `verdict.may_assert_answer`，否则挂 `REFUSAL` 拒绝（参考答案缺失/隔离时不引导揭晓）。揭晓文案固定带 `answer_status`/`review_status` 与"未经教研签署，以复核结论为准"。每轮 `scaffold_prompt` 来自 `_scaffold_hint`：优先 `repository.get_requirement(rid)` 的 title+locator 口径（带 `mapping_status`），退到 `knowledge_node_ids[0]`，再退到"本题未标注考点"。题不在库（`load_question` 为 None）返回 `NOT_IN_LIBRARY` 且 `grounded_in_library=False`；`_explanation` 取 `extra.llm_analysis_result.result.analysis` → `content.analysis`/`record.analysis`。模块级 `generate_hint(..., tier="research_internal")` 是独立入口的 classmethod。
- `sparks_chain.py`（271 行）—— `SparksChainEngine.explain(question_id, user_selected_option=None, node_id=None) -> SparksThreeChainResponse`，三条链的取数来源写死在模块 docstring：链 1 `key_clue_localization` 取 `_draft_analysis` 的 `key_info`（`extra.llm_analysis_result.result.analysis`，状态取 `extra.analysis_status`，缺省标 `draft(llm)`），退到纯解析文本首句，再没有就明说"本题未存有题目专属解析草稿"；链 2 `option_discrimination` 由 `_discrimination` 出：规范化 `content.options`、`option_compare` 草稿，比对所选与库内答案键仅当 `verdict.answer_status in LETTER_ANSWER_STATUSES` 且 `may_assert_answer`（`answer_letter` 抽字母），非字母键参考答案时 `matches_reference=None` 并解释无法比对，不断言时挂 `ANSWER_UNAVAILABLE`；链 3 `knowledge_provenance` 由 `_provenance` 出：逐条 `exam_requirement_ids` → `repository.get_requirement` → `gate.classify_requirement(...).citable` 过了才引 standard_id/title/content/locator，全空时 notice"该题在库内没有可引用的权威条款，解析仅基于题目自身文本"，并带 `source.files`/`source.verified`。非 `verified` 的解析草稿一律冠 `UNREVIEWED_ANALYSIS_NOTICE`；`verdict.usable=False` 走 `_blocked`（不渲染正文，指路 `审查/待复核清单.md`）；未入库返回模块常量 `NO_RECORD`。类方法 `generate(..., tier="research_internal")` 供直接调用。
- `__init__.py`（4 行）—— 转出 `TutorQAAgent`。

## 改这里之前要知道的

- 答案可见性只由 `TrustGate` 的 verdict 决定（`may_assert_answer`/`answer_visibility`），别在引擎里加"看起来像答案就报答案"的捷径；未过门禁时 `answer_visibility="none"` 是硬口径，`tests/test_services_data_source.py` 会断言讲解卡正文不断言答案。
- 解析草稿大多还是 `draft(llm-v2)` 未复核状态，新代码引用解析文本必须带出处状态标注，不许把草稿当权威讲解。
- `web/app.js:112` 以 `mode:'socratic_hint'` 依赖 `guiding_question`+`scaffold_prompt` 两个字段拼提示，改响应字段名要连带前端；`services/app.py` 的 `/api/v1/qa/stream` 同理透传 mode 缺省 `sparks_three_chain`。
