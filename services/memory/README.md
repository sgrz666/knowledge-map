# services/memory/ —— 学习状态门面：一次作答怎么变成掌握度记录、复习队列与可核对的收据

这里是作答之后落状态的一层：`MemoryReviewAgent.process_event` 接收 `ErrorReviewEvent`，核对对错、跑五维错因归因、推 FSRS 间隔、按单一公式更新掌握度，并把掌握度/错题/事件收据写进持久化存储。上游写入方是提交链路（`services/web/service.py::Workbench.submit` 逐考点调 `process_event(event, event_id=...)`、`services/app.py` 的 `POST /api/v1/memory/review`）；下游读取方是组卷层（`services/practice` 拿 `due_question_ids`/`weak_node_ids`）、排期层（`services/planner/scheduler` 拿 `store` 的到期队列与持久化掌握度）和 `services/learning/` 闭环。状态文件默认在仓库根 `.local_state/memory.sqlite3`（不提交，属机器上的学习者数据），环境变量 `KNOWLEDGE_MAP_STATE_DIR` 可改目录——测试就是这么指向临时目录的。口径（提交 f52f19c3）：掌握度与错因只读学习者自己的证据——申报的题目难度与申报的当前掌握度不进公式与归因树。改动跑 `python -m pytest tests/test_services_memory.py -q`，全 Agent 回归 `python -m pytest tests/test_services_all_agents.py -q`，收据"认输入不认事件号"的验收在 `tests/test_acceptance_gate.py`。

## 文件清单

- `agent.py`（208 行）—— `MemoryReviewAgent`。构造：`store` 缺省取 `default_store()`（进程级 SQLite 单例），`repository` 缺省 `get_repository()`，核对门写死 `TrustGate("research_internal")`（注释：让调用方自选档位=自选更宽的核对口径）。`process_event(event, *, record_attempt=True, event_id=None) -> ReviewBundle`：传了 `event_id` 就走 `store.run_once(event_id, event_fingerprint(event), lambda: 递归自身)` 的幂等收据路径（见 `receipt.py`）；否则 ① `_reconcile` 用 `reconcile_verdict(record, event.selected_option, event.is_correct)` 定对错——`is_correct` 是申报不是判决，与库内答案键矛盾时以库内为准并 `logger.warning`；判据两边都没有时返回 `_not_attributable`：不改掌握度、不进队列，followup 直说"系统不虚构对错"。② FSRS 评分：答错=1(Again)；答对且（耗时>45s 或改过选项）=2(Hard)、耗时<10s 且零改动=4(Easy)、其余=3(Good)。③ 归因：答错走 `ErrorAttributionEngine.attribute(event, persisted_mastery=existing.mastery_score)`，无持久化记录时 notice 声明"错因里没有认知盲区这一格"；答对给中性占位（category=CARELESS、category_name="掌握巩固"、confidence=1.0）。④ `FSRSModel.step` 推进状态；`retrievability` 上报的是"这次距上次复习隔了几天"按曲线衰减（无历史记 1.0），不是恒满分的 0 天。⑤ 掌握度全库唯一公式 `mastery_score = (c_count+1)/(p_count+2)`（该考点累计正确率的拉普拉斯平滑）；旧公式 `(0.7*acc + 0.3*(1-申报难度*0.4))*R` 的两个因子都被废弃（申报难度不得参与推断、方向还是反的）。⑥ 写 `store.put(UserMasteryRecord)`；`record_attempt=True` 时 `store.log_error` 记题级错题行（`due_at` 取新 FSRS 到期时间）。只读接口 `get_user_mastery`/`due_question_ids`/`weak_node_ids`/`_prior_error_entry` 供 practice/planner 消费。
- `fsrs.py`（143 行）—— `FSRSModel`，FSRS-v4 数学核，无 I/O。参数全部是类常量：`FACTOR = 19/81`、`DECAY = -0.5`（保证 R(S,S)=0.90 恰成立）、`REQUEST_RETENTION = 0.90`、首次稳定度 `INIT_STABILITY = {1:0.4, 2:0.9, 3:2.4, 4:5.8}`、首次难度 `INIT_DIFFICULTY = {1:7.5, 2:6.2, 3:5.0, 4:3.5}`。`retrievability(elapsed_days, stability) = (1 + FACTOR*t/S)^DECAY`；`next_interval(stability, target=0.90)` 反解天数、下限 1.0；`step(current_state, rating, now=None) -> (FSRSState, next_days)`：首评按 INIT 表初始化（rating=1 记 `state="relearning"`、lapses+1），复评难度 `D' = clamp(D - 0.7*(rating-3), 1, 10)`，稳定度答错 `max(0.2, min(0.4, S*0.25))`、答对按幂律增长式（bonus 0.75/1.0/1.35 对应 Hard/Good/Easy，growth 夹在 1.1–3.5），产出 `FSRSState(stability, difficulty, due_date, state, reps, lapses, last_review)`。
- `attribution.py`（106 行）—— `ErrorAttributionEngine.attribute(event, *, persisted_mastery)`，五维错因决策树（规范 §4.5），短路顺序即优先级：主观题 → `EXPRESSION_DEFICIT`（有 `subjective_rubric_misses` 引前三条、confidence 0.88，否则 0.75）；`time_spent_seconds <= 6.0` 或（题干含否定词且 <12s）→ `CARELESS 审题疏漏` 0.85；>150s → `TIME_PRESSURE 策略不当` 0.80；`is_typical_distractor` 或 `option_flip_count >= 2` → `MISCONCEPTION 概念混淆` 0.82；`persisted_mastery is not None 且 < 0.35` → `BLINDSPOT 认知盲区` 0.90（记录为 None 就不声称盲区——旧写法回退读调用方申报的 `current_node_mastery`，注释指出那等于引用"一段从未存在过的历史"）；兜底 `MISCONCEPTION 理解偏差` 0.70。全部输入是学习者行为轨迹 + 他自己的持久化记录，`event.question_difficulty`/`current_node_mastery` 两个申报字段不进任何分支。
- `receipt.py`（80 行）—— 事件收据："event_id 说这是哪一次作答，fingerprint 说那一次到底答了什么"。`fingerprint(payload)` = sha256(按 key 排序的 JSON)；`event_inputs(event)` 列出进摘要的 13 个提交字段（user_id/exam/question_id/node_id/is_correct/selected_option/time_spent_seconds/option_flip_count/has_negation_in_stem/is_typical_distractor/is_subjective/subjective_rubric_misses/question_difficulty），`event_fingerprint(event)` 是二者组合；`verify_receipt(event_id, stored, given)` 在任何学习写入之前裁决：同 id 同输入→回放首次结果，同 id 改过输入→抛 `ReceiptConflict`（`CONFLICT_DETAIL` 解释为什么既不能回放"答错了"给改了答案的提交、也不能重跑计两次），stored 为 None（指纹上线前的旧收据）→抛 `LegacyReceipt`。注意：`event_inputs` 摘要了申报字段 `question_difficulty`（判定不消费它，但改动请求会使其成为"另一次作答"），代码未含 `current_node_mastery`——模块 docstring 与这行代码的口径有出入，动它前先对 docstring 与 `tests/test_services_memory.py::TestEventReceipts` 核实预期。
- `store.py`（315 行）—— 持久化。`state_dir()`：`KNOWLEDGE_MAP_STATE_DIR` 环境变量覆盖，否则 `<仓库根>/.local_state`（`REPO_ROOT = parents[2]`）。`InMemoryMasteryStore`：测试/一次性脚本用的内存版（dict 存储，同样实现 `run_once` 收据）。`SqliteMasteryStore(path=None)`：默认 `<state_dir>/memory.sqlite3`，`threading.RLock` + `check_same_thread=False`；`_SCHEMA`（`SCHEMA_VERSION = 2`）建 `meta`、`user_mastery(user_id, node_id 主键, record_json)`、`error_log`（`UNIQUE(user_id, question_id)`，索引 `(user_id, due_at)`）、`memory_events(event_id 主键, user_id, fingerprint 可空, result_json)`；对旧库用 `PRAGMA table_info` 检查后 `ALTER TABLE` 补 `user_id`/`fingerprint` 列，旧行 fingerprint 留 NULL 即"无法核对"（由 `LegacyReceipt` 拒回放）。`run_once` 在 `BEGIN IMMEDIATE` 事务里"查重—执行—落收据"，异常整体回滚。查询：`due_question_ids(user_id, now=None, limit=20)` 取 `due_at <= now 或 NULL`，按到期时间+错误数倒序；`weak_node_ids(user_id, limit=5)` 用 `json_extract` 按考点平均掌握度升序（相对最低，不是过线判定）；`unverifiable_receipts()` 数旧收据；`clear(user_id=None)` 连收据一起清（注释：只清掌握度会留下收据让下次提交被当"已记过"回放）。`default_store()` 进程级懒单例。
- `__init__.py`（6 行）—— 转出 `MemoryReviewAgent`、`ErrorAttributionEngine`、`FSRSModel`（store/receipt 不在包门面里，按需从子模块 import）。

## 改这里之前要知道的
