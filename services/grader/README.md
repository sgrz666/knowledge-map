# services/grader/ —— 主观题判分门面：量规从哪里取、双轨怎么分岔、为什么只给反馈不出分

这里是"学生作答文本 → 质性反馈（或签署后的分数）"的一层：`SubjectiveGraderAgent` 是唯一的对外判分入口，负责量规寻源、信任裁决与拒判；`rubric_engine.grade` 是双轨（CET 整体档位 / NTCE 加权分析）共用引擎；`evidence.py` 提供两种模式共用的采分点比对。调用方：`services/app.py` 的 `POST /api/v1/grade/subjective`、`services/web/service.py::Workbench.submit`（单选/多选之外的题型在提交时自动送判分）、`services/master/agent.py`。量规只读两处库内实体——`数据集/教资/rubrics/*.json`（A.6 加权量规，`repository.RUBRIC_DIR`）与 `数据集/四六级/ontology/scoring_rubrics.jsonl`（CET 档位量规，`repository.CET_RUBRIC_FILE`），由 `KnowledgeRepository.find_rubric/rubrics()` 统一出，本目录代码不许自己开文件；不出分是常态——目前两库所有量规都未签署（`verdict.may_score=False`），所以响应一律 `feedback_only=True`、分数需具名教研在 `审查/待复核清单.md` 签署后才存在。改动跑 `python -m pytest tests/test_services_grader.py -q`（`TestGraderUnsigned`/`TestGraderSignedPath`/`TestGraderLibraryTruth` 三类），量规双轨契约在 `tests/test_rubric_contract.py`，判分不冒充验收在 `tests/test_acceptance_gate.py`（A4、§10"不在未签署量规上出分"）。

## 文件清单

- `agent.py`（261 行）—— `SubjectiveGraderAgent.grade(request: SubjectiveGradingRequest) -> UnifiedSubjectiveGradingResponse`，按模块 docstring 的四条职责分步：① 题面裁决 `_input_gap`：`repository.load_question(question_id)` 未命中 → `not_in_library`，命中但 `has_answerable_text(stem, options)` 为假（只剩套名）→ `stem_extraction_gap`，两者都走 `_refuse` 出 `review_status="refused_ungradable_input"` 的拒判响应（`INPUT_GAP_REFUSAL` 两套话术、`total_score=None`、不落待复核队列——队列只收"需要教研看的判分"，输入缺口没有判分可看）。② 量规寻源：`gate.classify_rubric(repository.find_rubric(rubric_id/task_type/exam))`，`answer_status` 一律从题记录读、请求模型里没有参数位（`scoring_mode: Literal["auto", ...]` 缺省 "auto"）。③ 双轨分岔：`mode = request.scoring_mode`（holistic_band/analytic_criteria 直取）否则 `MODE_BY_EXAM = {"CET-4": "holistic_band", "CET-6": "holistic_band", "NTCE": "analytic_criteria"}`，再兜底 analytic_criteria；随后调 `rubric_engine.grade(request, mode=..., rubric=self.repository.rubrics().get(rubric_id), verdict=..., record=..., llm_payload=..., tier=...)`。④ 状态与出口：`_stem_mismatch_notice` 用 `SequenceMatcher` 比对调用方题干与库内题干（去空白截 600 字，含包含关系），低于 `STEM_SIMILARITY_FLOOR=0.6` 时声明"判分与反馈以库内为准"；`gate.classify_record(record).servable_in_paper=False` 时把响应强制降为 `quarantined_for_human`/不出分；`SafetyGuard.sanitize_grading_response(response, rubric_signed=...)`（`services/common/safety.py`）做最后一道措辞消毒；feedback_only 或消毒隔离且未入队时 `_enqueue` 写队列行（reason 为 `rubric_signature_required` 或 `rubric_missing_for_task`，detail 里 note"脚本不得代签"）。`_llm_payload`：LLM 只在非 rule_only 时产 `{"evaluation_summary", "revision_advice"}` 措辞草稿，prompt 明文禁止输出分数与签署结论。
- `rubric_engine.py`（231 行）—— 模块级 `grade(req, *, mode, rubric, verdict, record=None, llm_payload=None, tier="research_internal")`，双轨共用。采分点 `evidence.expected_points(rubric, req.reference_answer, record)` + `coverage` 得 `(hits, ratio)`；`may_score = verdict.may_score`，`tier=="published"` 且未签署时强制 False 并挂 `PUBLISHED_REFUSAL`。出分路径（仅签署量规可达，`score_basis="signed_rubric"`，`review_status` 按有无 llm_payload 记 `llm_graded`/`heuristic_graded`）：`_score` 中 holistic_band 取 `nearest_band_descriptor(bands, ratio)` 的 `raw_score_range`，报区间中点 `min((low+high)/2, max_score)`（档位是区间不是天花板）；analytic_criteria 逐维度 `weight_score × min(1, ratio×DIMENSION_CREDIT=1.0)` 累加，`_level_for_score` 把得分落回库内 `criteria_levels[].score_range` 档位名。不出分路径：`total_score=None`、`score_basis="unsigned_framework"`（量规在库）或 `"none"`（缺量规）、`review_status="quarantined_for_human"`，holistic 轨给 `band_reference`（库内档位描述原文引用 + `BAND_REFERENCE_NOTICE`"不是报道分或官方阅卷结果"），analytic 轨给 `rubric_points_hit` 命中表，两轨都附 `dimension_feedback` 质性反馈。`max_score` 取 `req.max_score` → `rubric.total_score`/`max_score_raw` 顺序。`_summary`/`_advice` 生成统计句与漏项清单，LLM 草稿一律冠"（未复核）"字样。模块 docstring 记录本文件取代了旧的 `cet_holistic.py`/`ntce_analytic.py` 两台引擎（各自抄了一份量规影子数据且未签署也出分，A1/A4 双双违例）。
- `evidence.py`（216 行）—— 双轨共用取证。`overlap(point, answer)` 用 `difflib.SequenceMatcher(autojunk=False)` 数连续重合块（≥2 字符），返回重合比例与最长共享串——注释写明为什么不用关键词表（库内没有逐点关键词，分词结果依赖自家 tokenizer）。`match_point` 阈值：hit ≥0.5、partial ≥0.2、否则 missed。`expected_points(rubric, reference_answer, record)` 顺序即口径：库内量规 `question_specific_points` → 库内 `content.answer`/`content.reference_answer` 按 `_SEGMENTED` 正则（1、/(1)/①/第一、…）分点切分 → 调用方自备 `reference_answer`（provenance 明写"不代表教研核定的判分口径"）→ 题内嵌练习框架 `record.rubric`/`content.rubric` 的 `key_points`/`points`（"库内题目内嵌练习框架"，只是采分点兜底来源，不是量规实体）；最多取 8 点并带 provenance 字符串进响应 notices。`coverage` 折出 hit=1.0/partial=0.5/missed=0 的覆盖率。`feedback_dimensions(rubric, mode)`：holistic 读量规自带 `feedback_dimensions`（name/required_evidence/aggregation），缺了退到 `bands` 逐档；analytic 读 `dimensions`——两者都不补足（内置四维度模板就是旧影子数据）。`nearest_band_descriptor`/`pick_level` 只做位置映射（库内 levels 一律 best-first，不重排不改名），`quote_answer` 引用学习者自己的原句（≤80 字）作证据。
- `__init__.py`（5 行）—— 转出 `SubjectiveGraderAgent` 与 `grade`。

## 改这里之前要知道的

- 量规只许经 `repository.find_rubric/rubrics()` 读：签署状态在文件里的 `review.status`，量规签名有且只有一个读取方（A1/A2）；`__pycache__/` 里残留的 `cet_holistic`/`ntce_analytic` 字节码对应的源文件已删除，别按 pyc 恢复旧引擎。
- "不冒充官方分"是三层叠加：未签署量规引擎根本不出分；`BAND_REFERENCE_NOTICE` 声明档位列名是转录原文、仅练习定位用；`SafetyGuard.sanitize_grading_response` 兜底消毒响应措辞。绕过任何一层都会红 `tests/test_acceptance_gate.py` 的判分不冒充项与 `tests/test_services_grader.py`。
- 调用方自带的 `reference_answer` 只能兜底且来源必须写进 notices——否则任何人都能传一份自定答案顶掉教研口径，响应却还挂着库内 question_id（模块 docstring 第 4 条）。
- 主观题"没有题面就没有判分口径"：`refused_ungradable_input` 故意不进待复核队列，改这里前先想清楚队列语义（收的是判分结果，不是输入缺口）。
- `__pycache__/` 是生成物。
