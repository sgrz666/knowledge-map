# services/web/ —— 网页工作台的接口层：`/api/v1/web` 路由、请求私有的模型出口、卷面与提交的 SQLite 存储

这一层是浏览器唯一能敲到的门。模块 docstring 就写了口径：`Tools own facts; the model only narrates their results` —— 事实全部出自各能力 agent 与知识库索引，本目录只负责把它们拼成页面能渲染的 JSON，并把"模型只转述、不裁决"这条落在 `provider.py`。写它的是 `services/app.py`（`app.include_router(build_router(AuthContext.from_header))`，紧接 `app.mount("/assets", StaticFiles(directory=WEB_ROOT, check_dir=False))` 把本仓库 `web/` 挂成同源静态目录），读它的是 `web/app.js` 与 `web/workflows.js`（浏览器 `fetch('/api/v1/...')`）。运行时状态写进 `.local_state/workbench.sqlite3`（不入库，`.gitignore` 已排除）。

改动后跑（本轮实测：`tests/test_web_workbench.py + tests/test_services_api.py` 合计 **34 passed / 71.08s**）：

```powershell
python -m pytest tests/test_web_workbench.py tests/test_services_api.py -q
```

## 接口一览（浏览器实际会打的 `/api/v1/web/*`）

- 本目录直接注册：`GET bootstrap`、`GET audio/{question_id}`、`GET paper/{paper_id}`、`POST model/test`、`POST chat`、`POST practice`、`POST submit`、`POST profile`、`POST feedback`。
- 子路由（各自目录有自己的 README）：`POST learning/diagnostic/start|result`、`learning/plan|plan/current|plan/replan`、`learning/task/start|complete`、`learning/interview/session|session/current|session/answer`（`services/learning/router.py`）；`POST knowledge/tree|knowledge/node`（本目录 `knowledge.py`）；`POST exam/start|exam/latest|exam/{session_id}/state|advance|submit|finish`（`services/exam_sessions/routes.py`）。
- 另有 `services/app.py` 上的旧接口仍被前端使用：`POST qa/query`（"给我一点提示"的 `mode='socratic_hint'`）。

## Key 的取法：只在页面内存里活一次

1. 输入在 `web/index.html` 的 `#api-key`（`type=password`），`web/app.js` 存进 `state.key`；`persist()` 写 localStorage `knowledge-map-prefs` 的字段只有 `user/tier/exam/level/subject/base/model`——**没有 Key，也没有运行时令牌**，刷新页面就得重填（设置区块文案原文："Key 仅保存在当前页面内存"）。
2. 传输：`config()`（`{base_url, model, api_key: state.key}`）随每次主动请求放进请求体——`web/chat` 的 `model_config_input`、`web/model/test` 的 body。服务端 `ModelConfig.api_key` 是 `SecretStr`，只在 `client_for(req.model_config_input)` 里 `get_secret_value()` 解一次，用来 new 一个当次请求的 `LLMClient`；不进环境变量、不进 SQLite、不进日志。
3. 出口三道闸：`models.py::https_endpoint`（入参形状）、`NoRedirect`（重定向绝不带着 Bearer 头再跳）、`getaddrinfo` 公网判定 + `_carried_by_system_proxy` 例外；再加 `generate()` 的 `[已隐藏]` 兜底替换。
4. 门钉用例（`tests/test_web_workbench.py`，本轮随全量跑过）：`test_config_key_is_not_returned_or_shared`（`/model/test` 响应文本不含 `private-test-key`，且此时 `GET /api/v1/health?probe=false` 的 `llm_mode` 仍是 `rule_only`——证明请求 Key 没污染进程级客户端）、`test_invalid_model_config_never_echoes_a_key`（`http://127.0.0.1:8000` + Key → 422 且响应不含 Key）、`test_model_guard_checks_the_endpoint_it_will_actually_dial`（fake-ip `198.18.0.253` + 系统代理在场时必须放行）。
5. 网页链路**不看** `KNOWLEDGE_MAP_LLM_BASE_URL/API_KEY/MODEL` 这三个环境变量（那是 `services/llm/client.py::LLMClient._provider_from_env` 给其它链路的入口）；`client_for(None)` 就是规则模式，所以环境里有 Key 也不会让工作台偷偷请求模型。

## SSE 不在这个目录

`services/web/*` 全是普通 JSON 请求-响应：`routes.py` 只用到 `FileResponse`，前端 `web/app.js::api()` 用 `fetch` + `res.json()`，并有 180s `AbortController`。流式在 `services/app.py`：`_sse(events)` 用 `StreamingResponse(media_type="text/event-stream")`，`GET /api/v1/qa/stream` 与 `GET /api/v1/master/stream` 通过 `_run_in_thread` 把事件按 `status → card → done` 发出（异常时 `error → done`），`tests/test_services_api.py` 里 `test_master_stream_emits_status_card_done`（第 270 行）与 `test_qa_stream_reports_error_event_for_unknown_id`（第 281 行）分别断言 content-type 与错误事件。想在网页工作台加流式，要动的是 `services/app.py`，不是这里。

## 无 Key 时仍然可用的功能

`client_for` 返回 `LLMClient(RuleOnlyProvider())`，`RuleOnlyProvider.generate` 抛"未配置 LLM key，RuleOnlyProvider 不发起任何模型调用"，`LLMClient.generate` 在 `is_rule_only` 分支 openly 返回 `mode='rule_only', ok=False, errors=['no_llm_provider_configured：…']`，`narrate` 再补一句"请在模型与设置中填写 Key 后测试连接"。上面这些都不经模型，因此照常用：组卷（`/practice`）、提交判分与错因/复习安排（`/submit`）、主观题规则反馈（`SubjectiveGraderAgent`）、学情与画像（`/profile`）、知识点树与考点详情（`/knowledge/*`）、服务端计时模考全链路（`/exam/*`）、学习闭环（`/learning/*`，含面试训练的文字反馈）、题库审计（`/bootstrap` 的 `library`）、内容问题入队（`/feedback`）。`/chat` 在没有模型时返回的是 `service.py` 里那几段规则文本（考纲条款原文 / 召回材料标题 / "当前范围没有召回可用证据"），`reply` 字段有内容、`model.ok=False`，页面因此显示"规则答复 · 模型未参与"。真正被模型影响的只有"把工具结果讲成一段话"这一步。

## 改这里之前要知道的

- `.local_state/workbench.sqlite3`（含 `-wal`/`-shm`）是**本机运行态**，不入库：清了它等于丢掉所有卷与提交历史，`latest_paper` 找不到卷、错题复习与计划任务都会断线。测试与手工验收先设 `KNOWLEDGE_MAP_STATE_DIR`（`services/learning/store.py` 从 `PRAGMA database_list` 取父目录，所以 `learning.sqlite3` 会跟着一起搬到隔离目录）。
- `Workbench` 是**路由级单例**，`store.py` 的互斥只是 `threading.RLock`（进程内），`docs/web_agent_architecture.md` 记的口径是"默认只运行一个 worker"，`start_web.ps1` 也确实不带 `--workers`。加并发进程前要先想清楚 SQLite 与内存审计缓存（`_audit_generation`）怎么办。
- `build_router` 里的 `auth_dependency` 与 `context.require(TrustTier.RESEARCH_INTERNAL)` 是这套接口唯一的鉴权面（`KNOWLEDGE_MAP_RUNTIME_TOKEN` 由 `services/app.py::AuthContext` 用 `secrets.compare_digest` 比）。`tests/test_web_workbench.py::test_web_requires_runtime_token` 钉住"设了环境变量后无头 401"。别在子路由里加自己的依赖绕过它。
- 幂等口径不要拆：`submit()` 先 `verify_receipt` 再判分；`submission_fingerprint` 覆盖了 `answer/time_spent_seconds/option_flip_count`，所以"重试时改答案"必须是 409，而不是重新判一次。前端 `web/app.js::renderQuestion` 已经按同一口径把首次参数冻结进 `localStorage['pending-submit:<paper>:<question>']`，两边任一改动都要同步（`tests/test_web_workbench.py::test_saved_submission_replays_only_that_exact_attempt` 会红）。
- `practice()` 里那几行"下发前的处理"是安全边界：`item.pop('answer')` 防透答案、`audio_url` 只在真有文件时给、缺图必须 `input_blocked=True`（`test_missing_figure_submission_is_refused` 钉提交侧）。`mock_exam` 的 notices 文案是"不属于严格全真模考""不提供官方报告分"两条口径的来源，别当成装饰文本删。
- `published` 档在这里被硬挡三处：`chat()` fail-closed、`profile()` 空画像、`knowledge.py` 空列表/409。库里 `signed_questions` 当前为 0（`test_web_entry_and_bootstrap` 断言 `data['library']['signed_questions'] == 0`），任何"发布档也能练"的改动都会绕过 TrustGate。
- 考试分钟数不归本目录：`service.py` 只透传 `time_limit_minutes` 和 notices，收卡与时序在 `services/exam_sessions/`，题量配速在 `services/common/pacing.py`；`services/exam_sessions/README.md` 记了 `test_no_service_layer_ships_its_own_exam_length` 那道 AST 门。
- `store.py` 的 `ALTER TABLE` 补列是给"指纹上线前写的行"留 `NULL` 的兼容路径，别改成回填：原请求的选项修改次数没存过，猜出来的指纹会让一次作答被计两次。
