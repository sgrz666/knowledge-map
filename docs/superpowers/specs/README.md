# docs/superpowers/specs/ —— 每轮交付的设计稿（范围锁定、改动边界、验证口径），先于 plan 存在

一轮设计一份 `YYYY-MM-DD-<主题>-design.md`：回答"这轮做成什么样、哪些模块可以动、怎么算验证过、明说做不到什么"。它是同主题 plan 的上位约束——plan 拆步骤，spec 定边界。

## 文件清单

- `2026-10-11-web-agent-design.md`（29 行，手写，入库）—— 网页端备考智能体设计稿。锁定的范围：
  - **用户流程（6 步）**：选范围默认研究档 → 设置里填 HTTPS Base URL/模型名/Key（Key 仅页面内存、逐请求传后端，不进 localStorage/SQLite/日志/全局环境变量，默认参数出处标了 DeepSeek 官方文档与查询日期）→ 问答只解释检索到的真实证据并携带引用 → 七种练习与模考走真实题池、库内答案键判分、主观题量规未签署只给反馈 → 计划/画像/复习用持久化记录、面试支持教案与试讲转写 → 完整性面板逐学段科目显示缺口、可导出可纠错。
  - **改动边界（白名单模块）**：`services/web`、`web/`（独立 HTML/CSS/JS、textContent 渲染、移动端自适应）、`services/knowledge`（只补读取与完整性汇总，不制造知识/答案/审核状态）、`services/planner`+`practice`（学段筛选贯穿、空池不退）、`schemas`；外加修复 memory→attribution 的 `persisted_mastery` 接口不一致。
  - **验证**：新增 API 回归覆盖配置隔离、Key 不回显、模型失败、引用越界、研究/发布门禁、学段过滤、提交幂等、材料展示、拒绝跨卷提交；完整跑 tests 与知识库门禁；真实浏览器测全流程；**没拿到用户真实 Key 就不声称验证过 DeepSeek 线上调用**。
  - **已知边界**：零人工签署题、零实测校准、published 空池；语音依赖浏览器；教资规格无逐节时序只做整卷计时；不预测通过率；只监听 127.0.0.1，不上公网。

## 改这里之前要知道的

- 设计稿定稿后不回改；范围变了就写新一轮 spec，老文件保留为当时承诺的证据（"不声称验证过线上调用"这类边界声明就是靠留痕才有效）。
