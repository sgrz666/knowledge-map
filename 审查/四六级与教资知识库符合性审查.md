审查日期：2026-10-03。依据：[应试考证功能设计与技术支撑：以教资和四六级为例.md](../应试考证功能设计与技术支撑：以教资和四六级为例.md)，重点对照 §2.2、§3.1–3.4 及 F1/F2 所需数据。检查对象是 `数据集/四六级/`、`教资KB/` 的现有静态产物及其生成代码。

**结论：两套库均部分符合，尚不能按文档的完整知识库要求验收。文件组织和结构化存储已基本成形，知识点与能力的语义挂载、权威依据、可用答案及解析仍有明显缺口。当前适合继续整理资料、试验检索和筛选题目；不足以直接支撑可信的能力诊断与个性化路径。**

本次只新增审查产物，未修改题库、图谱、原始资料或设计文档。

## 1. “形式符合”应怎样判断

文档要求的不只是将 PDF/CSV 转成 JSONL，也不只是增加知识点 ID 字段。应能从一道题追到具体知识点、能力、考试要求及出处，并能够从知识点反查题目与资源。

JSONL、Markdown 卡片、关系表和图数据库都可以承载这种模型。层级编号或文件名不同不构成不符合；缺少实际映射、把模块名当细知识点、只有占位字段则构成实质缺口。

L5 用户掌握度属于运行时数据：静态知识库不必提前存储真实用户记录。四六级已有 `mastery_template.json`；教资保留知识点 ID 挂载位置。这一设计方向合理。是否实现了作答记录、更新掌握度、诊断和推荐，需要另行检查应用，不能通过静态文件宣称已完成。

## 4. 必须补齐的实质缺口

### 4.1 四六级“100% 挂知识点”包含错误的兜底挂载

**严重性：高。证据确定。** 1,120 道选词填空与 1,125 道长篇阅读，共 2,245 题，仅挂 `[cet4.read, cet4.listen]` 或六级对应的两个模块根节点，`ability_ids=[]`。阅读题同时被标为听力，且没有具体知识点和能力。

实例：`数据集/四六级/questions/cet4/2015-06_p1.jsonl` 第 26 行，`cet4-2015-06-p1-reading-26`。题型是选词填空，但知识点为阅读与听力根节点。

原因位于 `scripts/migrate_v2_schema.py` 的 `qnodes()`：TYPE_NODES 中的 `read.cloze` 等字符串已含点号，当前条件没有给它们补上 `cet4.`/`cet6.` 前缀，随后被有效 ID 过滤器全部移除，触发根节点兜底。旧版已迁移记录又被幂等逻辑跳过，因此只改迁移函数并重跑未必能修复现有数据。

**建议：**修正 ID 生成逻辑，并针对已迁移的 2,245 题重新挂载；由知识点重算能力，验证题目模块与知识点所属模块相容。随后人工核验标签含义。

### 4.2 教资知识点覆盖不全，学科粒度较粗

**严重性：高。证据确定。** 2,391 题没有任何知识点。学科大纲普遍只有“学科专业知识 / 课程与教学理论 / 教学设计 / 教学实施与评价”四个节点。例如地理题“能够反射无线电波的大气层”，当前只挂 `ntce.chuzhong.dili.s1`，名称为“学科专业知识”。

这可以支持按大模块检索，却不足以诊断“大气垂直分层”这一具体考点是否薄弱，也难以生成准确的补弱任务。

**建议：**按实际大纲条目拆到可教学、可练习、可评估的知识点，再打标。没有依据的题进入待标队列，不用模块根节点填充来制造覆盖率。

### 4.3 教资图谱链条不完整，能力层覆盖很低

**严重性：高。证据确定。** 教资 `edges.jsonl` 中没有任何 L2 模块 → L3 知识点的边。L3 节点虽然有 module 属性，但仅将 nodes/edges 导入图数据库后，不能沿关系边遍历文档要求的完整“考试 → 模块 → 知识点 → 题目”链条。

能力支持边仅 23 条，直接覆盖 186 个知识点中的 23 个。生成脚本的 `WRITTEN_SUBJECTS` 仅含公共笔试科目，未覆盖初高中学科卷和面试。题目记录本身也没有能力 ID。

先修关系的生成方式是“按大纲顺序把顶层节点连成链”，并标注待教研审核。大纲的展示顺序不能直接等同于真实先修关系。

**建议：**补模块到顶层知识点的实际关系；补学科和面试能力映射；定义是否允许能力沿子节点继承，并让应用与导出规则一致；先修边根据概念依赖审核。

### 4.4 权威标准仍未落到可核验的来源和条目

**严重性：高。证据确定。** 教资 34 份 outline 全为 `verified=false`；45 个 standard 图节点均未核验，均无原文文件或 URL。四六级标准对象只有名称与机构/编号，知识点未提供可核验的标准条目、页码或来源字段。

原始题库来源和官方考试依据是两种不同的追溯链，题目能找到原 CSV/文档不等于知识点已对齐官方考纲。`source.verified` 也应与题目审核状态区分：教资生成脚本对所有题目固定写 True，而其中 13,409 题为待复核或低置信。这一布尔值不能当作专家审核证据。

此外，需求文档 §3.1 和四六级 `ontology/standards.json` 将 CSE 写成 `GB/T 41671-2022`，编号有误。[教育部发布页](https://www.moe.gov.cn/jyb_sjzl/ziliao/A19/201807/t20180725_343689.html)列出的《中国英语能力等级量表》编号是 **GF 0018—2018**；[全国标准信息公共服务平台](https://std.samr.gov.cn/gb/search/gbDetailed?id=E3C42FB7ACFC2086E05397BE0A0A19F0)表明 GB/T 41671-2022 对应《化学纤维 溶剂残留量的测定》。本次未修改原文。

**建议：**先校正依据编号，保存官方原文及版本、生效日期、来源；为知识点建立具体大纲/能力描述条目映射。当前统一填写的 CSE 等级也应在核验映射依据后再作为正式评价依据。

### 4.5 题目可用性和评分支撑不足

**严重性：高。证据确定。** 四六级 4,459 题没有答案，所有题目解析正文为空；教资仅 71 题解析非空，主观题缺少结构化评分点与可计算量规。两库所有难度值为空，不能据此做有难度校准的自适应诊断。

审核状态上，四六级 177 题为 needs_fix，5,117 题为 auto_parsed；教资 3,742 题低置信、9,667 题待复核、1,091 题已清洗。已清洗不等于专家确认答案与解析正确。

另有四六级 7 题、教资 23 题的单字母答案不在该题当前选项键中，属于需要复核的结构异常，不能仅凭此确定是答案错误还是选项提取丢失。例如 `cet4-2021-06-p2-listening-1` 的答案为 J。部分听力题还需要按题组关联音频和播放区间；当前题目未提供这些字段。文档允许四六级全真模考暂缓，因此该项按未来支撑缺口记录，不作为当前必须做全真模考的要求。

**建议：**先形成可发布题目白名单：内容完整、答案有效、知识点/能力/要求映射完整、审核通过；缺答案和低置信题不用于自动判分、诊断或分数预测。补齐主观题参考答案、评分点、维度与样例，再进入 AI 辅助评价。

### 4.6 四六级资源 ID 与追溯路径存在问题

**严重性：中至高。证据确定。** 范文库 177 条中有 58 条重复 ID 的额外记录，翻译库 193 条中有 72 条，高频词组库 1,406 条中有 7 条。以 ID 作为向量库或数据库唯一键时，会出现重复插入失败或覆盖。

资源来源字段也不够规范：大纲词来源路径含 `...`，模板仅填文件名，部分范文/译文把多个文件用分号拼在一个字符串。它们无法按当前约定的单文件路径直接解析；这不代表原始文件一定不存在，而是追溯指针不具备稳定的机器可解析形式。

**建议：**合并同一任务的重复资源，或为不同版本/来源分配不同 ID；来源改成多项结构化引用，保存完整相对路径和页码/定位信息。通用资源的考试范围可用 exams 列表或明确的图谱推导规则表示。

### 4.7 说明与统计存在口径漂移

**严重性：中。证据确定。** 四六级 README 写阅读语料 431 条、needs_fix 95 条，当前实际分别为 449 与 177。stats.json 将范文和译文覆盖都记为 0，但迁移后的 extra.model_essay/extra.reference 实际非空分别为 68 和 116；统计脚本读取旧字段会误判。

**建议：**按迁移后的 schema 重建统计，明确“记录条数 / 唯一任务数 / 有参考答案或范文的任务数”分别怎样计算。

## 5. 推荐补齐顺序

1. **先修复已有错误：**四六级 2,245 题错误兜底标签、重复资源 ID、答案与选项异常、旧字段统计。
2. **再完善知识模型：**教资细粒度知识点、未挂载题、模块到知识点关系、学科/面试能力映射，以及经审核的先修关系。
3. **落实权威追溯：**纠正标准编号，接入官方原文、版本与条目映射，区分来源核验和内容审核。
4. **构建可使用的发布子集：**补答案、解析、评分量规及适当难度标注。先保证一批题满足全部规则，逐步扩展。
5. **再验证应用闭环：**作答事件 → 用户×知识点掌握度 → 错题归因 → 复习与路径更新，另行检查产品实现。

不必先换数据库或增加题量。当前的 JSONL 与 Markdown 组织可以保留，优先补齐数据含义与关系。

## 6. 如何使用与复核

查看本报告了解差距；`知识库形式审查结果.json` 包含全量计数、分科目结果和问题样例；`知识库形式审查.ipynb` 保存检查代码及结果，可在 Jupyter 中复核。

在仓库根运行以下命令，即可重新扫描并更新审查 JSON/notebook；脚本不会写入两套知识库。

```powershell
python .\审查\知识库形式审查.py
```

若系统 Python 不可用，本次使用的是 Codex 自带 Python：

```powershell
& 'C:\Users\sg\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' .\审查\知识库形式审查.py
```

修复后的验收建议：发布题目必备知识点、能力和考试要求映射；ID 唯一；引用存在且语义一致；需要判分的题有有效答案；图谱能双向遍历；主观题有量规。再抽样完成“选知识点 → 获取完整题目与材料 → 作答判分 → 解释知识点/能力/来源”的流程。真正的用户掌握度更新需要在应用中测试。

当前使用建议：将资料作为检索与整理候选集；需要刷题时只挑选完整且经核验的记录，并排除重复/低置信记录。不要直接把全库统计标签当作用户能力结论。

## 7. 检查边界

本次全量检查主 JSONL、静态本体及图谱引用，检查了字段缺失、ID 唯一性、关联完整性、先修环、分科目覆盖、源路径和说明统计。没有逐题核定答案正确性，没有全量验证 Markdown 卡片与 JSONL 的同步程度，也没有运行学习产品。目录中“2026 年最新”不代表 2026 年真题已拆题；现有 README 明确说明 2026.6 扫描件待 OCR。本次缺少可比历史快照，不判断数据质量的时间趋势。
